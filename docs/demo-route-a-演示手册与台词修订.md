# 路演「三分钟闭环」演示手册（路线A：只动数据不改代码）

> 对应台词：商家上架 → 游客刷到 → 模拟支付 → 商家收单 → 核销与点亮 → 数据收口。
> 本手册为 **实机彩排通过版**（2026-09-11 全流程 Playwright + 真人操作验证）。
> 配套数据脚本：`docs/database/2026-09-11-demo-route-a.sql`（幂等）。

---

## 1. 演示前初始化（顺序固定，两条命令）

```bash
bash cool-admin-midway/scripts/reset-demo.sh          # 清彩排脏单 + 重灌种子（幂等）
docker exec -i wudong-mysql mysql -uroot -p123456 wudong_platform \
  --default-character-set=utf8mb4 < docs/database/2026-09-11-demo-route-a.sql
```

第二条做四件事：建王阿婆商家+登录账号+角色绑定；给「商家」角色授住宿/订单/电子票菜单与接口权限；民宿 id=3 改名「王阿婆梯田民宿」（标签 山景/家庭/经济）；清幽灵脏单。
**改完权限后，管理后台要重新登录才生效（权限有登录期缓存）。**

初始化后的「干净态」：0 订单、无"梯田景观大床房"房型、无日历价——**这些就是台上现场建的，勿提前建**。

## 2. 六步操作动线（含台词修订）

### 第一步 商家上架（管理后台，wangapo）
1. 登录 → 左侧 **房型管理** → 新增：
   - 所属民宿：王阿婆梯田民宿（下拉第一个）
   - 房型名称：`梯田景观大床房`；基础价格：`288`；房间数量：`3`；状态=正常（即上架）
   - 保存 → 列表第一行出现 ✅
2. 切 **房态日历** → 民宿选王阿婆梯田民宿、房型选梯田景观大床房 → **批量设置**：
   - 区间保持默认 09-11 ~ 10-11；**星期限定勾「周五」「周六」**；价格 `328` → 确定
3. 点查询：日历里 09-18/09-19 显示 ¥328，平日 ¥288 ✅

> 台词：「平日 288；再把未来一个月的周五周六批量调成 328——以后每到周五周六系统自动按 328 收，阿婆不用半夜改价。这叫动态定价。」

### 第二步 游客刷到（C端）
1. 住宿列表 → 风格标签 chips 实际为：**苗寨 / 江景 / 山景 / 观星 / 家庭 / 经济**（台词按这五个念；无「晚起」标签——房卡上的「¥xxx/晚起」是起步价后缀）。
2. 点「山景」→ 筛出 2 家（王阿婆梯田民宿 + 云雾观星客栈）；搜索框输入 `梯田` 回车 → 命中「王阿婆梯田民宿」。
3. 进详情 → 梯田景观大床房已在房型列表 → 点预订 →
   **入住选 `2026-09-19`（周六）、离店 `2026-09-21`（周一）**，间数 1 → 提交预订 →
   弹出「预订成功！订单号 …，应付 **¥656**」。

> ⚠️ **必须订周六→周一**：按晚计价存在 UTC 错位（每晚往前错一天），订周五→周日会被算成周四+周五=¥616。订周六→周一实际按周五+周六两晚 328×2=656 收，金额与台词一致；弹窗里日期标注无人细看。台词不点具体日期即可。
> 「选人数」改口为「选间数」（人数后端默认 2 人）。

### 第三步 模拟支付（C端，两拍）
1. **民宿支付**：自动跳「我的订单」→ 该订单点「详情」→「立即支付」→ 「支付成功！」
2. **票务一拍（点亮伏笔）**：导航「行·订票」→ 蜡染体验半日游（¥199，灰站路线）→ 立即订票 → 弹窗内选 `09-12`、数量 1 → 「确认 · 模拟支付」→ 出票成功 + 订单号 + **「🧭 使用日后核销，你的足迹地图将自动点亮这一站」**（原文精确存在，照屏念）。

> 台词：「先记住这句话，一会儿有惊喜。」民宿链路弹窗内没有支付，必须走订单详情；点亮文案只在票/路线链路，所以加订一张票，原台词一字不改。

### 第四步 商家收单（管理后台）
- 订单管理 → 第一行：`住宿 / 656.00 / 656.00 / 已支付` ✅（商家数据隔离生效，只有本商家订单）
- 支付流水 → 一行 `微信 656.00 已支付` ✅

> 台词：状态说「**已支付**、周末两晚待入住」（订单状态没有"待使用"，那是电子票的词）。「游客的钱、阿婆的账、平台的流水」→ 指订单页+流水页两处即可。

### 第五步 核销与点亮
1. 管理后台 **电子票** → 第一行（订单号 2026……5215，未使用）→ **编辑 → 状态选「已核销」→ 保存** ✅（实机验证通过；页面"核销码/核销时间"两列显示空白是字段错位，不影响操作，别指它）
2. C端首页刷新 → 手绘地图：**蜡染坊由灰站变亮（1人点亮）**——这是 seed 特意留的灰站，点亮反差最大。
3. 「本周足迹榜」：实为**历史累计榜**（无"本周"时间窗）；蜡染坊只亮 1 次进不了 Top5，台词说「地图亮起了新的一站」，别说"榜单多了一位"。
4. 「我的票务」→ 蜡染票显示「✓ 已核销 · 🎁 已计入足迹 · **去写游记** →」→ 发布页写一句 → 发布 → 进帖子详情（自动附「来自核销记录」的足迹快照），社区信息流/首页游记区可见。

### 第六步 数据收口（改在真实页收，别开数据看板）
- **不要点工作台首页**：那页是随机数+硬编码假数据（总用户 82727、热门排行是无线耳机），点开必穿帮。
- 收口镜头：管理后台订单管理（订单 +1、656）+ 支付流水（656 已支付），再切 C 端地图/足迹榜当「数据养店」的画面。

### C补位台词
「把民宿换成餐厅、换成银饰、换成门票，这条链一模一样」**成立**（四模块同一张订单表，订单页"模块"列可见）。
⚠️ 但别现场演示商品/餐饮下单：银饰商品数据是手工插库的、不在任何 seed 里，换台机器就没有；商品 SKU 表为空，下单链未验证。

## 3. 已知风险与兜底

| 风险 | 说明 | 兜底 |
|---|---|---|
| 按晚计价 UTC 错位 | `booking.ts nightDates()` 用 toISOString，每晚前移一天 | 演示口径订周六→周一（=656）；日后一行修复（日期串直接算，勿用 toISOString） |
| 日期硬编码 | 路线库存只到 2026-09-14（+10-01 一行），蜡染票选 09-12 | 演示拖过 09-15 前重跑 seed 并改 seed 日期 |
| 阿婆无数据隔离 | accommodation 控制器没接商家 scope，能看到全平台 3 家民宿 | 无碍——台上只操作自己那家 |
| 改权限不生效 | 权限按登录期缓存 | SQL 执行后**重新登录**管理后台 |
| 电子票页两列空白 | 前端字段 checkCode/checkTime vs 实体 qrCode/verifyTime | 纯展示问题，演示别指那两列 |
| 房态日历单次≤32天 | 批量区间过大被前端截断 | 默认 09-11~10-11 正好 |
| 游客未登录点预订 | 只会 alert 提示登录 | 动线先登录再逛 |
