# base T3：cart + operate + sensitive + 收藏白名单扩容 实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 收尾 base 层剩余四件互不依赖的小模块——`cart`（购物车）、`operate`（平台运营：banner/announcement/finance_record）、`sensitive`（敏感词 DFA），并把 `user_favorite.targetType` 白名单扩为需求文档并集。

**Architecture:** 三个独立 cool-admin 模块 + member 一行扩展。cart/operate/sensitive 互不依赖，可任意拆分会话并行（各自从 `feature/base-merchant` 切分支）；本会话顺序执行合并为一个分支。

**Tech Stack:** 同 T1/T2

**Spec:** `docs/superpowers/specs/2026-09-09-platform-base-design.md` §5.5/§5.7/§5.8/§8-D3/D4

## Global Constraints

- 沿用 T1/T2 全部约束（表名 verbatim、camelCase、显式 `prefix`、`pageList` 命名、每文件一次 boot、`ok(null)` 丢键）。
- **分支**：`feature/base-cart` 等并行时各自切出；本会话顺序执行用单分支 `feature/base-t3` 从 `feature/base-merchant` 切出。
- **测试手机号**：cart `13000230001/2`、收藏扩容 `13000430001`（operate/sensitive 无需注册用户，注意全量号唯一即可，前缀可复用）。

### Task 1: 分支 + FAVORITE_TYPES 并集扩容

- Modify: `src/modules/member/service/favorite.ts`——`FAVORITE_TYPES = ['product', 'restaurant', 'hotel', 'scenic', 'route', 'guide', 'post']`
- Test: `test/base-favorite-types.test.ts`——注册 `13000430001`，toggle `product`/`hotel` 成功（旧白名单会抛"收藏类型不正确"），`route` 回归不受影响
- 提交：`feat(base): 收藏类型白名单扩为七类并集（衣/食/住接入）`

### Task 2: cart 模块

- Create: `src/modules/cart/`（config/entity/cart.ts/service/cart.ts/controller/app/cart.ts）
- Test: `test/base-cart.test.ts`
- **实体** `cart`：userId、productId、skuId、quantity（default 1）、checked（default 1）；唯一约束 `(userId, skuId)`
- **CartService**：
  - `add(userId, productId, skuId, quantity)`——已存在同 sku 则数量累加（upsert 语义）
  - `update(userId, id, { quantity?, checked? })`——仅本人
  - `remove(userId, ids)`——仅本人
  - `pageList(userId, page, size)`——id 倒序
- C 端（需登录）：`POST /app/cart/add`、`POST /app/cart/update`、`POST /app/cart/delete`、`GET /app/cart/page`
- **测试**：未登录拦截；add→同 sku 再 add 数量累加；update 数量/勾选；delete 仅本人（他人 id 删不掉）；page 隔离
- 提交：`feat(base): 购物车 cart 模块（同 SKU 累加/仅本人变更）`

### Task 3: operate 模块

- Create: `src/modules/operate/`（config/entity/banner.ts+announcement.ts+finance-record.ts/controller/app/operate.ts/controller/admin/banner.ts+announcement.ts+finance.ts）
- Test: `test/base-operate.test.ts`
- **实体**（schema.sql verbatim → camelCase）：
  - `banner`：title、image、linkType（page/url/none）、linkValue、position（home/product/food…）、sort、startTime/endTime（transformerTime, nullable）、status（1启用 0禁用）
  - `announcement`：title、content(text)、type（1系统 2活动）、startTime/endTime、isTop、status（1发布 0草稿）、createdBy
  - `finance_record`：orderId、merchantId、orderAmount/commissionRate/commissionAmount/merchantIncome（decimal）、settlementStatus（1待结算 2已结算）、settlementTime、settlementBatch——本期只建表，无 add/update/delete
- C 端（**匿名**，IGNORE_TOKEN）：`GET /app/operate/banner?position=`（status=1、sort 升序）、`GET /app/operate/announcement`（status=1，isTop 优先）
- 管理端：`/admin/operate/banner`、`/admin/operate/announcement` 全 CRUD；`/admin/operate/finance` 仅 page/list/info
- **测试**：admin 录入用 service 直插（unittest 无 admin 会话）→ 匿名查 banner 按 position 过滤与排序、草稿/禁用不出现；announcement 置顶优先；三个 admin 路由 401；`/app/operate/banner` 未带 token 返回 1000（验证 IGNORE_TOKEN 生效）
- 提交：`feat(base): 平台运营 operate（banner/公告匿名查询 + finance_record 表）`

### Task 4: sensitive 模块

- Create: `src/modules/sensitive/`（config/entity/word.ts/service/sensitive.ts/controller/admin/word.ts）
- Test: `test/base-sensitive.test.ts`
- **实体** `sensitive_word`：word（unique）、status（1启用 0禁用）
- **SensitiveService**：
  - `check(text): Promise<{ hit: boolean, words: string[] }>`——DFA（Trie）扫描启用的敏感词；命中→调用方置待人工复审（spec §5.3 机审流程）
  - `addWord(word)`/`removeWord(id)`——供 admin 与测试用
- 管理端：`/admin/sensitive/word` 全 CRUD
- **测试**：service 加词→check 命中与未命中、禁用词不参与匹配、多词同时命中；admin 路由 401
- 提交：`feat(base): 敏感词 sensitive 模块（DFA 过滤服务供社区/评价复用）`
