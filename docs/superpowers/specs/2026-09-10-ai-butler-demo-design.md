# 云游乌东 · AI管家演示壳子（ai-butler-demo）设计文档

## 1. 背景与目标

路演演示②「游客动动嘴，AI跑断腿」需要首页有一个「AI管家」入口：悬浮圆圈 → 对话框，一站式完成衣食住行的推荐与下单，配合演讲者的 7 拍台词完成现场演示。

**定位：demo/壳子。**

- 对话流程是**预排好的固定时间线**（playback），没有真实 NLP/LLM——chips、台词、节拍全部提前编排；
- 三条预订（住宿/餐位/路线票）走**真实后端接口**，演示完可打开「我的订单/票务/预订」看到真记录；任一失败自动降级为演示卡（标小字「演示数据」），保证现场不断戏；
- 真 AI 上线时，仅将 `script.ts` 的时间线数据源替换为接口返回，UI 与调度不动。

## 2. 演示叙事（7 拍 ↔ UI 节拍）

| 拍 | 演示者动作 | UI 呈现 |
|---|---|---|
| 1 说需求 | 点 chip 或输入完整需求句 | 用户气泡上屏；管家气泡「包在我身上～」 |
| 2 需求识别 | — | 接力面板节点①亮起；弹出抽取结果卡（日期/人数/预算/偏好等 6 项） |
| 3 检索生成 | — | 节点②亮起 + 「正在检索房型/餐厅/票务…」思考动效 → A/B 两张候选小卡 |
| 4 执行推荐 | — | 节点③亮起；A 方案置顶高亮，展开明细与总价，附预算余额彩蛋（腊肉梗） |
| 5 一键预订 | 点 A 卡「一键预订」 | 三接口真实下单 → 成功卡（订单号/入住码样式）+ 常驻预订条逐项点亮 + 跳转入口 |
| 6 回传反馈（可砍） | 点 chip「换个离梯田更近的」 | 方案重排，B 顶上，附「步行到梯田五分钟」文案 |
| 7 跨类推荐（加分） | — | 管家主动递上衣/食小卡（苗绣围巾/一块腊肉 🥓），深链 `/products`、`/farm-products` |

拍 6 标记为**时间不够最先砍**；拍 7 为加分拍。第 5 拍收口台词：「从我说那句话到现在，不到一分钟。」

## 3. 交互与视觉

### 3.1 悬浮圆圈
- 右下角固定 56px 圆钮，🤖 图案 + CSS 脉冲光环动画；点开后变为 ✕。
- 仅首页显示：挂载于 `App.vue`，路由判断 `path === '/'`（比塞进 HomeView 干净，组件不随页面卸载重建）。

### 3.2 对话窗
- 右侧抽屉，宽约 400px；纵向三区：消息流（自动滚底）/ 接力面板 / 输入区。

### 3.3 接力面板（RelayPanel）
- 三节点横排：`需求识别 → 检索生成 → 执行推荐`，节点间连线。
- 三态：未到（灰置）/ 当前（呼吸光圈 + 连线流光）/ 已过（常亮）。

### 3.4 思考动效
- AI 气泡「正在思考」三点跳动动画（0.8~1.2s）；
- 检索阶段节点②转圈 + 文案轮换（房型库/餐厅库/票务库）；
- 所有节拍时长集中在 `script.ts` 常量，总时长目标 ~90s、可整体调快调慢。

### 3.5 方案小卡（PlanCard）
- 一行式紧凑卡：图标 + 名称 + 关键信息（ nights/人数/距离标签）+ 价格；点击展开明细行。
- A/B 两卡，A 置顶高亮；「一键预订」按钮在卡底。
- 三态：候选（默认）/ 推荐中（高亮）/ 已预订（打勾 + 订单号）。

### 3.6 chips 递进（固定脚本，按节拍切换组）
- R1 开场：`🧳 带爸妈去乌东玩` / `🍜 乌东有什么好吃的` / `🏠 住哪里比较安静`
- R2 主线细化：`预算一千五` / `想要安静` / `想吃长桌宴`
- R3 方案出来：`就按 A 方案订` / `换个离梯田更近的`
- R4 预订完成：`再看看别的` / `就这样，谢谢管家`
- **递进机制（主线前缀段）**：点 R1「带爸妈去乌东玩」→ 管家「好嘞，两位老人我记下了～预算和偏好也告诉我呗」→ chips 换 R2；逐个点选（每点一个：用户短气泡 + 管家一句确认「✓ 要安静，懂」）；集齐后管家汇总复述完整需求，汇入主线拍 2。开场也可直接在输入框打整句需求（原剧本「五个条件，一句话」的演法），**两种开场汇入同一条主线时间线**。
- **吃/住支线**：R1 的`好吃的`/`住哪里`进入各自小剧本（长桌宴介绍卡 / 民宿推荐小卡），结尾 chip「帮我一起安排 →」引回主线前缀段。
- 输入框仍可自由输入：命中主线关键词按主线走，其余一律回兜底话术（见 §7）。

### 3.7 语气
管家文案口语化 + emoji：开场「包在我身上～」、识别「我听明白了：**两位老人、两晚、要安静**」、推荐「A 方案帮你算好了，还剩 102，够带一斤腊肉回家 🥓」。

### 3.8 常驻「本次预订」胶囊条
对话窗底部常驻：🏠 住宿 / 🍜 长桌宴 / 🎫 路线票 三个小图标，预订成功逐个点亮；点图标直达对应页面，旁有「全部订单 →」。

## 4. 剧本引擎（`script.ts`）

- 数据结构：`Beat = { id, delayMs, actions: Action[] }`；`Action` 为可区分联合：`userMsg / aiMsg / thinking / nodeLight / cards / chips / book / jump`。
- 剧本 = `Beat[]`，四条时间线（主流程含递进前缀段 / 吃支线 / 住支线）+ 拍 6 重排增量，全部内联在常量里；金额、抽取卡 6 项、方案明细均为静态数据。
- 播放器：`async + sleep` 链驱动，组件只负责按 action 渲染消息流/面板状态；彩排快捷方式：**双击悬浮圈 → 时间线直接跳到拍 5**（需求已完整、方案已出），不进常规 UI。
- 触发路由：chips 点击 / 输入关键词 → 选择对应剧本；只做三条支线 + 主线的固定路由，无模糊匹配。

## 5. 真实预订链路与降级

三条预订的前端封装**全部复用现成 API**，不新增接口层：

| 项 | 调用 | 关键参数（剧本预设） | 成功跳转 |
|---|---|---|---|
| 住宿 | `accommodationApi.bookingCreate` | 云上人家·吊脚楼双床房 roomTypeId、10-01→10-03、1 间 | `/order/:orderNo` |
| 餐位 | `foodApi.createReservation` | 长桌宴 restaurantId=3、seed 新增时段、10-01 午市、2 人 | `/my/reservations` |
| 路线票 | `travelApi.bookingCreate` | 梯田摄影一日游、10-01、2 张 | `/my/tickets` |

- 前置：未登录 → 卡内提示「请先在右上角登录」（与 BookingModal 同语义），不弹强制跳转。
- 餐位预订的 contactName/contactPhone：取登录用户昵称与手机号，取不到时用剧本预设的测试账号值兜底。
- 「一键预订」串行调三接口；**任一失败/超时（5s）→ 该项降级演示卡**（右上角小字「演示数据」），其余继续，戏不断。
- 降级卡与成功卡同构，仅来源标记不同；预订成功后方案卡转「已预订」态并写入常驻条。
- 餐位预订后端无支付环节 → 文案如实用「预订成功」（非「已支付」）。
- 金额展示原则：**以服务端真实计价为准**，剧本台词数字与 seed 对齐（见 §6），实现时逐项核对。

## 6. seed 调整（`cool-admin-midway/scripts/seed.js`，幂等追加）

1. 民宿改名：hotel 1 →「云上人家」；其「吊脚楼双床房」价格 520 → 316（两晚 632 ✓）。房态无日历行时后端回退房型默认库存，国庆日期可直接预订。
2. 长桌宴时段：`time_slot` 表当前无数据 → 为餐厅 3 补午市/晚市时段行（字段按 entity），否则餐位预订无可选时段。
3. 路线库存：为路线 2（晨雾梯田摄影一日游 ¥299）补 2026-10-01 库存行（total 20 / sold 3）。
4. 台账对齐：A 方案总价 = 632（住宿）+ 168（长桌宴，展示值）+ 598（299×2）= **1398**，预算 1500 剩 **102**——演示台词中 1432/68 按此微调；方案明细里的名称以 seed 真实名为准（「田园徒步路线」→「梯田摄影一日游」）。
5. B 方案映射：hotel 2（坐落于梯田之上）作为「离梯田更近」的 B 卡，仅展示不需真实可订。

## 7. 错误处理

- 接口异常/超时 → 降级演示卡（§5），控制台透出后端原始报错便于现场排障；
- 未登录 → 引导文案；
- 「一键预订」防重复提交（paying 态禁用）；
- 自由输入未命中 → 兜底话术：「演示版先试试下面的快捷提问～」并重出当前 chips 组。

## 8. 测试与质量（验收门槛）

- `script.ts` 纯函数：剧本结构完整（三支线可走通）、chips 组按节拍切换、兜底路由、金额明细合计正确（~8 例）；
- `AiButler.vue`：开合、发送后按拍推进、思考态渲染、常驻条随预订点亮（~6 例）；
- `PlanCard.vue`：候选/高亮/已预订/降级四态渲染，展开明细（~4 例）；
- `npm test` 全绿（现有用例 + 新增 ~18 例）；
- seed：本地重灌验证幂等，且三条预订在演示账号下真实成功一遍。

## 9. 非目标

真 NLP/LLM、模糊语义匹配、餐位支付、新增独立页面、移动端适配、管理端改动、多轮自由对话。

## 11. 分支/协作

- 分支 `feature/ai-butler-demo`，基于 `origin/main`（cfed6a8，含住宿预订落地 + 个人中心域）。
- 演示环境前提：后端起好 + seed 重灌 + 测试账号登录（README 已有账号约定）。

## 12. 风险与依赖位

| 风险 | 缓解 |
|---|---|
| 现场后端/网络故障 | 三接口全部有降级演示卡，最坏情况整场走演示数据 |
| seed 未重灌导致真实预订失败 | 同上降级；演示前 checklist：重灌 seed → 三连预订彩排一遍 |
| 演示账号脏数据累积 | 附清理 SQL（票/订单/预订按测试账号范围删除），彩排后复位 |
| 台词数字与真实计价不一致 | §6 台账对齐原则，实现时逐项核对一遍 |
